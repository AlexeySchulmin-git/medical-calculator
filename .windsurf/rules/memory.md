# Правила работы с проектом Medical Calculator

## 🚨 ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК ДЕЙСТВИЙ

1. **ВСЕГДА** читать `docs/CODEINDEX.md` ПЕРЕД тем как лезть в код
2. **ВСЕГДА** читать `docs/DECISIONS.md` перед архитектурными изменениями
3. **ТОЛЬКО ПОСЛЕ** этого использовать `grep_search` или `read_file`

## 🏗️ АРХИТЕКТУРНЫЕ ПРАВИЛА

### Запреты
- **НЕЛЬЗЯ** менять структуру папок `src/` без согласования
- **НЕЛЬЗЯ** использовать MySQL в Next.js API - только PostgreSQL в `medical-api-server.cjs`
- **НЕЛЬЗЯ** смешивать CommonJS и ES modules в одном файле
- **НЕЛЬЗЯ** добавлять новые зависимости без проверки `package.json`

### Обязательные паттерны
- API routes: только в `src/app/api/` (Next.js) или `medical-api-server.cjs` (Express)
- Бизнес-логика: только в `src/lib/`
- Компоненты виджета: только в `src/widget/`
- Типы: только в `src/types/`

### Структура проекта
```
medical-calculator/
├── medical-api-server.cjs     # Express сервер (PostgreSQL)
├── src/
│   ├── app/api/              # Next.js API routes
│   ├── lib/                  # Бизнес-логика
│   ├── widget/               # React-компоненты калькулятора
│   └── types/                # TypeScript типы
├── docs/                     # Документация
└── .windsurf/               # AI-ассистент правила
```

## 🔍 ПОИСК КОДА

### Приоритет поиска
1. **Индекс** → `docs/CODEINDEX.md` (быстрее всего)

## 📝 ОБНОВЛЕНИЕ ПАМЯТИ

### 🚨 ОБЯЗАТЕЛЬНО после каждой задачи
1. **Обновить `docs/CODEINDEX.md`** если добавлены/удалены модули
2. **Обновить `docs/DECISIONS.md`** если изменилась архитектура
3. **Создать bead** в `src/docs/beads/` по правилам `.windsurf/rules/beads.md`
4. **Обновить `docs/CURRENT_TASK.md`** для следующей сессии

### Что обязательно фиксировать в CODEINDEX:
- **Новые API эндпоинты** (добавить строку в таблицу)
- **Новые UI компоненты** (указать файл и назначение)
- **Изменения в логике расчёта цен** (обновить описание функций)
- **Интеграции с внешними сервисами** (добавить в таблицу интеграций)
- **Новые файлы в `src/lib/`** (библиотеки, утилиты)
- **Изменения в структуре БД** (обновить граф зависимостей)

### Процесс обновления CODEINDEX:
1. **Найти новые файлы**: `find_by_name` по маске `**/*.{js,ts,jsx,tsx}`
2. **Определить назначение**: кратко описать функциональность
3. **Найти ключевые функции**: основные экспорты/эндпоинты
4. **Обновить статистику**: пересчитать количество модулей
5. **Обновить граф зависимостей** если нужно

### Что обязательно фиксировать в DECISIONS:
- **Архитектурные изменения** (новые паттерны, рефакторинг)
- **Изменения в структуре папок** (добавить в раздел "Что нельзя менять")
- **Новые внешние интеграции** (сервисы, API, БД)
- **Изменения в технологиях** (замена библиотек, фреймворков)
- **Миграционные решения** (планы переходов)

### Процесс обновления памяти:
1. **Сразу после завершения задачи** - обновить CODEINDEX
2. **Если изменилась архитектура** - обновить DECISIONS  
3. **Создать bead** - зафиксировать изменения
4. **Проверить актуальность** - убедиться что всё отражено

## 🎨 КОДИРОВОК СТАНДАРТЫ

### JavaScript/TypeScript
- ES6+ синтаксис
- Arrow functions для callbacks
- Async/await вместо Promise.then()
- JSDoc комментарии для функций

### React/Preact
- Functional components с hooks
- Props destructuring
- Состояние в `useState`
- Side effects в `useEffect`

### API
- RESTful принципы
- JSON responses
- Error handling с HTTP status codes
- Валидация входных данных

## 🔐 БЕЗОПАСНОСТЬ

- API ключи только в headers `x-api-key`
- SQL параметры только через prepared statements
- Валидация всех входных данных
- CORS только для доверенных доменов
